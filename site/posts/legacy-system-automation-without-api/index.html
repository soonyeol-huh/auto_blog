API가 없는 사내 시스템도 자동화할 수 있을까?

“우리 ERP는 너무 오래돼서 API가 없습니다.” 자동화 상담에서 자주 나오는 이야기입니다. 하지만 API가 없다는 이유만으로 자동화를 포기할 필요는 없습니다. 중요한 것은 가장 안정적이고 관리하기 쉬운 연결 방법부터 찾는 것입니다.

먼저 ‘API가 없다’의 뜻부터 확인해야 합니다

실무에서는 API가 없다고 생각했지만 실제로는 CSV 내보내기, 엑셀 업로드, 정기 파일 생성, 데이터베이스 조회 기능이 있는 경우가 많습니다. 자동화의 목적은 꼭 API를 쓰는 것이 아니라 사람이 반복해서 옮기는 데이터를 안정적으로 이동시키는 것입니다.

권장 순서: 공식 연동 기능 확인 → 파일 연동 → 안전한 DB 조회 → 브라우저 자동화 → 필요하면 중계 API 구축

API가 없을 때 검토할 4가지 연결 방법

방법적합한 상황주의점
파일 연동CSV·엑셀을 내보내거나 업로드할 수 있음파일 형식 변경, 중복 처리 확인
DB 조회데이터베이스 접근이 가능하고 조회 권한을 분리할 수 있음운영 DB 부하와 쓰기 권한 제한
브라우저 자동화사람이 웹 화면에서 반복 입력·조회함화면 변경, 로그인, 예외처리
중계 API여러 시스템이 같은 데이터를 반복 사용함초기 구축비와 운영 책임

1. 파일 연동: 가장 단순하지만 의외로 강력합니다

기존 ERP가 매일 특정 폴더에 CSV를 생성하거나 직원이 엑셀을 내려받을 수 있다면, 그 파일을 자동 수집해 정리하고 다른 시스템으로 전달할 수 있습니다.

예를 들어 매일 오전 직원이 ERP에서 재고 파일을 내려받아 쇼핑몰 상품과 비교하는 업무라면, 파일 생성 시점을 기준으로 자동 수집 → 상품 코드 정리 → 부족 재고 표시 → 담당자 알림까지 연결할 수 있습니다.

파일 연동이 좋은 경우

데이터 구조가 비교적 단순하고, 실시간까지는 필요 없으며, 기존 시스템을 크게 수정하기 어려운 경우입니다. API 개발보다 훨씬 작은 범위로 시작할 수 있다는 장점이 있습니다.

2. DB 조회: 읽기 전용으로 시작하는 것이 안전합니다

오래된 사내 시스템도 내부적으로는 데이터베이스를 사용하는 경우가 많습니다. 시스템 담당자와 협의해 읽기 전용 계정이나 별도 조회용 데이터베이스를 제공받을 수 있다면 자동화 시스템이 필요한 정보만 가져올 수 있습니다.

다만 운영 데이터베이스에 직접 쓰는 구조는 신중해야 합니다. 잘못된 입력 하나가 실제 주문·재고·정산에 영향을 줄 수 있기 때문입니다. 처음에는 조회와 분석부터 시작하고, 쓰기 작업은 별도 승인이나 공식 기능을 거치는 구조가 안전합니다.

3. 브라우저 자동화: 사람이 하던 화면 조작을 대신합니다

파일도 DB도 접근할 수 없다면 사람이 사용하는 웹 화면 자체를 자동화할 수 있습니다. 로그인 후 검색 조건을 넣고, 결과를 내려받고, 특정 값을 입력하는 작업이 대표적입니다.

다만 브라우저 자동화는 화면 구조가 바뀌면 수정이 필요합니다. 그래서 단순히 “클릭을 대신하는 봇”으로 만들기보다 실패 감지, 재시도, 로그, 담당자 알림까지 함께 설계해야 실제 운영에서 쓸 수 있습니다.

4. 중계 API: 연결이 많아지기 시작할 때 가치가 생깁니다

ERP 데이터를 대시보드도 쓰고, AI도 쓰고, 쇼핑몰 자동화도 쓰고, 영업 시스템도 쓰게 된다면 연결을 각각 따로 만들기보다 중간에 작은 API 계층을 두는 편이 관리하기 쉬워집니다.

예를 들어 ERP에서 가져온 상품·재고 데이터를 내부 표준 형식으로 정리한 뒤 중계 API가 제공하도록 만들면, 이후 새로운 서비스가 추가돼도 ERP에 직접 다시 연결하지 않아도 됩니다.

실제 업무 예시: 오래된 발주 시스템 자동화

한 유통회사가 매일 오전 다음 과정을 수작업으로 한다고 가정해보겠습니다.

  1. 판매 시스템에서 전날 주문 엑셀을 내려받습니다.
  2. 사내 ERP에서 재고를 조회합니다.
  3. 재고 부족 상품을 별도 엑셀에 정리합니다.
  4. 담당자가 공급사에 발주 메일을 보냅니다.

ERP에 API가 없더라도 주문 파일 수집과 정리는 자동화할 수 있고, 재고 조회는 DB 읽기 또는 브라우저 자동화를 검토할 수 있습니다. 마지막 발주는 금액이 큰 경우 담당자가 확인한 뒤 메일을 보내도록 남길 수 있습니다.

핵심은 전부 자동화하는 것이 아닙니다.
연결 가능한 구간부터 자동화하고, 위험한 결정에는 사람 승인을 남기는 것이 실제 운영에 더 적합합니다.

자동화 상담 전에 준비하면 좋은 정보

사용 중인 시스템 이름보다 실제 업무 화면과 파일 예시가 더 중요합니다. 담당자가 어떤 순서로 클릭하는지, 어떤 값을 복사하는지, 어떤 예외가 자주 발생하는지 보여주면 연결 방법을 훨씬 빨리 판단할 수 있습니다.

FAQ

API가 없으면 자동화가 불가능한가요?

아닙니다. CSV·엑셀 파일 교환, 읽기 전용 DB 접근, 브라우저 자동화, 별도 중계 API 같은 방법을 검토할 수 있습니다. 다만 각 방법의 안정성과 유지보수 비용은 다릅니다.

브라우저 자동화는 언제 쓰는 것이 좋나요?

공식 API나 안전한 파일·DB 연동 방법이 없고 사람이 반복적으로 화면을 조작하는 업무에 현실적인 대안이 될 수 있습니다. 화면 구조가 자주 바뀌는 시스템이라면 유지보수 계획이 필요합니다.

가장 먼저 확인할 것은 무엇인가요?

현재 시스템이 파일 내보내기·가져오기, DB 조회, 공식 연동 기능을 제공하는지부터 확인하세요. 화면 자동화는 더 안정적인 연결 방법이 없을 때 검토하는 편이 좋습니다.
