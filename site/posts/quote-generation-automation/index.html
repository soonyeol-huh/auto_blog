견적 요청 올 때마다 엑셀 열어 계산하고 계신가요?

이메일이나 카톡으로 "이 제품 500개면 얼마예요?"라는 문의가 오면, 담당자가 단가표 엑셀을 열고, 수량 할인을 확인하고, 견적서 양식에 옮겨 적어 PDF로 보내는 회사가 아직 많습니다. 견적은 요청마다 내용이 조금씩 다를 뿐 계산 방식과 문서 형식은 거의 같기 때문에, 구조만 잡으면 담당자가 처음부터 만들 필요가 없는 업무입니다. 이 글은 견적 요청 접수부터 금액 계산, 견적서 초안 생성, 발송 후 관리까지 어떻게 자동화하는지 정리했습니다.

견적 업무가 왜 담당자 시간을 잡아먹을까

견적 한 건은 생각보다 여러 단계를 거칩니다. 요청이 이메일, 카톡, 홈페이지 문의 폼, 전화로 흩어져 들어오고, 담당자가 그 내용을 읽어 어떤 품목을 몇 개 원하는지 파악하고, 단가표에서 가격을 찾고, 수량이나 거래처 조건에 따른 할인을 적용하고, 견적서 양식에 옮겨 적어 보내고, 며칠 뒤 답이 없으면 다시 연락합니다. 이 과정이 요청 건수만큼 반복되는데, 대부분 회사에서는 단가표도 견적 이력도 담당자 개인 폴더의 엑셀에 있습니다. 그래서 담당자가 자리를 비우면 견적이 멈추고, 담당자가 바뀌면 이전에 어떤 조건으로 견적을 냈는지 아무도 모르게 됩니다.

손으로 견적을 내면 생기는 문제

  • 답변이 늦어져 기회를 놓칩니다. 견적을 여러 곳에 동시에 요청하는 거래처라면 먼저 도착한 견적이 유리한 경우가 많은데, 담당자가 바쁘면 하루 이틀은 금방 지나갑니다.
  • 담당자마다 가격이 다릅니다. 같은 품목, 같은 수량인데 누가 견적을 냈느냐에 따라 할인율이 달라지면 거래처 입장에서는 신뢰가 떨어집니다.
  • 계산 실수와 옛날 단가가 섞입니다. 단가표가 여러 버전으로 돌아다니면 이미 바뀐 가격으로 견적이 나가고, 수주 후에 손해를 보거나 정정 연락을 해야 합니다.
  • 견적 이력이 남지 않습니다. 어떤 요청이 수주로 이어졌고 어떤 요청이 그냥 사라졌는지 모르니, 견적 조건을 어떻게 바꿔야 할지 판단할 근거도 없습니다.

이 문제들은 담당자의 실력 문제가 아니라, 반복되는 계산과 문서 작업을 사람이 매번 처음부터 하는 구조 자체에서 생깁니다.

자동화 구조는 네 단계로 나뉜다

견적 자동화라고 하면 영업 시스템을 통째로 도입해야 할 것 같지만, 실제로는 네 단계를 순서대로 연결하는 것입니다.

  1. 요청 접수와 구조화. 이메일, 카톡 채널, 문의 폼으로 들어온 요청을 한곳에 모으고, 자유롭게 쓰인 문장에서 품목, 수량, 희망 납기, 배송지 같은 항목을 읽어 정해진 형식으로 정리합니다. 이 단계에 AI를 씁니다.
  2. 금액 계산. 정리된 품목과 수량에 단가표, 수량 구간별 할인, 거래처 등급별 조건을 적용해 금액을 계산합니다. 이 단계는 AI가 아니라 회사가 정한 규칙으로 처리합니다.
  3. 견적서 초안 생성과 검토. 계산 결과를 견적서 양식에 채워 초안을 만들고, 조건에 따라 자동 확정하거나 담당자 검토 목록에 올립니다.
  4. 발송과 후속 관리. 확정된 견적서를 보내고, 유효기간과 응답 여부를 추적해 필요한 시점에 담당자에게 알립니다.

핵심은 역할을 나누는 것입니다. 해석은 AI, 계산은 규칙, 확정은 사람이 맡도록 설계하면 빠르면서도 금액이 틀리지 않는 구조가 됩니다.

어디에 AI를 쓰고 어디에 규칙을 쓰나

견적 자동화에서 가장 흔한 실수는 AI에게 가격까지 맡기는 것입니다. 단계별로 적합한 방식이 다릅니다.

단계처리 방식이유
요청 문장에서 품목·수량·조건 읽기AI표현이 매번 달라 규칙으로 다 적을 수 없음
요청 품목을 우리 품목 코드에 맞추기AI + 품목 마스터거래처가 부르는 이름과 내부 코드가 다른 경우가 많음
단가·할인·부가세 계산규칙매번 같은 결과가 나와야 하고 근거를 설명할 수 있어야 함
견적서 문서 생성템플릿양식은 고정, 내용만 바뀜
비표준 조건·할인 한도 초과 판단규칙 → 사람회사 정책 문제라 자동으로 결정하면 안 됨
거래처에 보내는 안내 문구 초안AI초안만 만들고 발송은 담당자가 확인

견적서 초안은 검토 큐를 거친다

모든 견적을 자동으로 보내는 것이 목표가 아닙니다. 확실한 건은 자동으로 확정하고, 판단이 필요한 건만 담당자에게 보이게 하는 것이 목표입니다. 예를 들어 단가표에 있는 표준 품목이고, 수량이 통상 범위 안이고, 할인율이 정해진 한도 안이면 자동 확정합니다. 반대로 단가표에 없는 품목이 섞여 있거나, 요청 수량이 평소보다 훨씬 크거나, 거래처가 별도 조건을 요구했거나, AI가 품목을 확신 없이 매칭했으면 검토 큐로 보냅니다. 검토 화면에는 원래 요청 문장과 정리된 품목 목록, 계산 근거를 나란히 보여 주어 담당자가 다른 파일을 열지 않고 바로 확인하고 수정할 수 있게 합니다.

담당자가 수정한 결과를 규칙에 다시 반영하세요. 어느 거래처가 항상 특정 품목을 다른 이름으로 부른다면 그 이름을 품목 별칭으로 저장하고, 특정 거래처에 늘 적용하는 조건이 있다면 거래처 조건표에 넣습니다. 그러면 검토 큐에 올라오는 건은 시간이 지날수록 줄어듭니다.

보낸 뒤가 더 중요하다: 후속 관리

견적서를 보내고 나면 대부분 회사에서는 거래처가 연락할 때까지 기다립니다. 하지만 견적에는 유효기간이 있고, 응답이 없는 견적은 시간이 지날수록 수주 가능성이 낮아집니다. 발송 후 며칠이 지나도 응답이 없으면 담당자에게 알리고, 거래처에 보낼 확인 연락 초안을 함께 붙여 줍니다. 유효기간 만료 전에는 연장 여부를 확인하라고 알립니다. 그리고 수주가 됐는지, 안 됐는지, 안 됐다면 이유가 무엇인지를 견적 건에 기록하게 합니다. 이 기록이 쌓이면 어떤 품목, 어떤 가격대, 어떤 거래처 유형에서 수주율이 높은지 데이터로 볼 수 있고, 그것이 다음 견적 조건을 정하는 근거가 됩니다. 수주된 견적은 그대로 주문과 청구의 출발 데이터가 되므로, 다시 입력할 필요도 없어집니다.

도입 전 체크리스트

  • 단가표가 한 곳에 최신 버전으로 관리되고 있나요? 여러 버전이 돌아다닌다면 그것부터 정리해야 합니다.
  • 수량 할인, 거래처 등급별 조건이 문서로 정리되어 있나요? 담당자 머릿속에만 있다면 먼저 적어 내야 합니다.
  • 견적 요청이 어떤 경로로 들어오는지, 경로별 비중이 어느 정도인지 파악하고 있나요?
  • 어떤 조건이면 담당자 검토 없이 보내도 되는지, 어떤 조건이면 반드시 검토해야 하는지 정할 수 있나요?
  • 지난 몇 달간의 견적서 파일이 남아 있나요? 있다면 자동화 결과를 검증할 좋은 기준이 됩니다.

자주 하는 실수

  • AI에게 가격 결정을 맡기는 것 — 같은 요청에 다른 금액이 나올 수 있고, 왜 그 금액인지 설명할 수 없습니다. 가격은 규칙으로 계산해야 합니다.
  • 단가표 정리 없이 자동화부터 시작하는 것 — 자동화는 잘못된 단가를 더 빠르게, 더 많이 내보낼 뿐입니다.
  • 모든 견적을 자동 발송하는 것 — 비표준 조건이 섞인 견적이 검토 없이 나가면 정정하는 데 더 큰 비용이 듭니다. 자동 확정 조건은 좁게 시작해 넓혀 갑니다.
  • 발송까지만 자동화하고 후속을 빠뜨리는 것 — 견적은 빨라졌는데 수주율은 그대로인 경우가 많습니다. 응답 추적과 수주 기록까지 포함해야 효과가 눈에 보입니다.

FAQ

품목마다 가격 조건이 달라서 규칙으로 만들기 어려운데 가능한가요?

전체를 한 번에 규칙화하려 하지 말고, 견적 건수가 가장 많은 표준 품목부터 시작하면 됩니다. 담당자가 실제로 계산하는 방식을 옆에서 보면 대부분은 단가표, 수량 구간별 할인, 거래처 등급별 조건 몇 가지의 조합입니다. 규칙에 넣기 어려운 특수 품목은 처음부터 담당자 검토 건으로 분류해 두면, 자동화 범위 밖의 건이 잘못 계산되어 나가는 일은 생기지 않습니다.

AI가 가격을 알아서 정하게 해도 되나요?

권장하지 않습니다. 가격은 회사가 정한 단가표와 할인 규칙으로 계산해야 매번 같은 결과가 나오고, 나중에 왜 그 금액이 나왔는지 설명할 수 있습니다. AI는 요청 문장에서 품목과 수량, 납기 같은 조건을 읽어 내는 역할에 쓰고, 금액 계산은 규칙에 맡기고, 최종 확정은 담당자가 하는 구조가 안전합니다.

거래처마다 요구하는 견적서 양식이 다른데 어떻게 하나요?

견적 내용(품목, 수량, 단가, 조건)과 견적서 양식을 분리해서 관리하면 됩니다. 내용은 한 곳에 구조화된 데이터로 저장하고, 양식은 기본 양식 하나와 주요 거래처별 양식 몇 개를 템플릿으로 준비해 두면 같은 데이터로 여러 양식의 견적서를 만들 수 있습니다. 처음에는 기본 양식 하나로 시작하고, 특정 양식을 요구하는 거래처가 있을 때 하나씩 추가하는 편이 현실적입니다.
