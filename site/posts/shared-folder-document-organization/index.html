"최종_진짜최종.pdf", 어느 게 진짜인가요?

공유 폴더를 열면 "견적서(수정).pdf", "계약서_최종_v3.docx", "스캔_0012.pdf" 같은 파일이 뒤섞여 있습니다. 필요한 문서 하나를 찾으려고 여러 폴더를 뒤지거나, 결국 담당자에게 메신저로 다시 보내 달라고 하는 일이 반복됩니다. 문서가 들어오는 순간 종류를 판별하고, 정해진 규칙대로 이름을 붙여 제자리에 두는 구조를 만들면 정리는 사람이 아니라 시스템의 일이 됩니다. 이 글은 그 구조를 단계별로 정리합니다.

공유 폴더는 왜 금방 다시 어질러질까

대부분의 회사가 한 번쯤은 폴더 구조를 새로 정하고 파일명 규칙을 공지합니다. 그런데 몇 달 지나면 다시 원래대로 돌아갑니다. 이유는 대개 비슷합니다.

  • 규칙을 지키는 일이 사람에게 맡겨져 있습니다. 바쁠 때는 일단 바탕화면이나 "임시" 폴더에 저장하고, 나중에 옮기는 일은 잊힙니다.
  • 문서가 들어오는 경로가 많습니다. 이메일 첨부, 메신저, 스캐너, 거래처 포털 다운로드 등 경로마다 파일명이 제각각입니다.
  • 버전이 파일명으로만 구분됩니다. "최종", "수정", "v2"가 붙은 파일이 여러 개 생기고, 어느 것이 실제로 확정된 문서인지 알 수 없습니다.
  • 찾는 사람과 저장한 사람의 기준이 다릅니다. 저장한 사람은 거래처별로, 찾는 사람은 월별로 생각하니 같은 문서도 못 찾습니다.

문제는 정리 의지가 아니라, 정리를 "저장한 사람의 추가 작업"으로 남겨 둔 구조입니다.

먼저 정할 것: 문서 종류와 파일명 규칙

자동화보다 먼저 필요한 것은 "어떤 문서를 어떤 이름으로 어디에 둘지"를 표로 적는 일입니다. 이 표가 곧 자동 정리의 규칙이 됩니다.

규칙은 처음부터 모든 문서를 다룰 필요가 없습니다. 가장 자주 찾고 가장 자주 헤매는 문서 3~5종부터 정하고, 나머지는 "분류 불가"로 두는 편이 오래 갑니다. 날짜는 YYYYMMDD처럼 정렬되는 형식으로, 거래처명은 거래처 마스터에 등록된 공식 명칭으로 통일해야 같은 거래처가 여러 이름으로 흩어지지 않습니다.

자동 정리 흐름: 수집 → 판별 → 추출 → 이름·위치 결정

  1. 수집: 문서가 들어오는 입구를 하나로 모읍니다. 특정 메일 주소로 온 첨부, 스캐너 저장 폴더, 공유 드라이브의 "받은 문서" 폴더처럼 감시할 위치를 정합니다.
  2. 텍스트 확보: PDF나 워드 문서는 텍스트를 바로 읽고, 스캔 이미지는 OCR로 텍스트를 만듭니다.
  3. 종류 판별: AI가 문서 앞부분을 보고 견적서·계약서·세금계산서 등 정해진 종류 중 하나를 고릅니다. 목록에 없는 종류를 새로 만들지 않도록 선택지를 고정합니다.
  4. 핵심 정보 추출: 파일명에 필요한 거래처명, 날짜, 문서 번호, 금액 등을 뽑습니다.
  5. 규칙 적용: 추출한 값을 위 표의 규칙에 넣어 파일명과 저장 위치를 만듭니다. 이 단계는 AI가 아니라 고정된 규칙이 처리합니다.
  6. 이동과 기록: 파일을 옮기고, 원래 이름·원래 위치·새 이름·새 위치·처리 시각을 정리 기록에 남깁니다.
핵심: AI는 "이 문서가 무엇이고 안에 어떤 값이 있는지" 읽는 데만 씁니다. "어떤 이름으로 어디에 둘지"는 사람이 정한 규칙이 결정해야 결과가 매번 같고, 나중에 규칙만 바꿔도 전체 정리 방식을 바꿀 수 있습니다.

거래처명·날짜·번호 추출AI + 규칙 검증추출은 AI가, 형식 확인과 거래처 마스터 대조는 규칙이 합니다

중복·버전 판단규칙파일 해시와 문서 번호로 같은 문서인지 기계적으로 확인합니다
애매한 문서 처리사람확신이 낮은 문서는 확인 대기함에서 사람이 결정합니다

추출한 거래처명은 그대로 쓰지 말고 거래처 마스터와 대조해 공식 명칭으로 바꿉니다. 마스터에 없는 이름이 나오면 새 폴더를 만들지 말고 확인 대기로 보내야 비슷한 이름의 폴더가 늘어나지 않습니다.

버전과 중복은 이름이 아니라 기록으로 관리한다

"최종", "수정" 같은 단어로 버전을 구분하면 결국 혼란이 생깁니다. 자동 정리에서는 다음처럼 처리하는 것이 일반적입니다.

  • 완전히 같은 파일: 파일 내용의 해시값이 같으면 중복으로 보고 새로 저장하지 않습니다.
  • 같은 문서의 다른 버전: 거래처·문서 종류·문서 번호가 같은데 내용이 다르면 같은 이름에 버전 번호를 붙이고, 최신본이 무엇인지 정리 기록에 표시합니다.
  • 확정본 표시: 계약서처럼 확정 여부가 중요한 문서는 서명본·날인본 여부를 사람이 확인해 표시하도록 합니다.
  • 삭제 금지: 자동 정리는 옮기고 이름을 바꿀 뿐 지우지 않습니다. 이전 버전은 보관 폴더로 옮깁니다.

공유 드라이브 서비스에 자체 버전 기록 기능이 있다면 함께 활용하되, 어떤 파일이 최신 확정본인지는 정리 기록에서 한눈에 보이도록 하는 것이 찾는 사람에게 더 편합니다.

도입 전 체크리스트

  • 정리할 문서 종류 3~5종과 파일명·폴더 규칙을 표로 정했는가
  • 문서가 들어오는 입구(메일, 스캐너, 다운로드 폴더)를 정했는가
  • 거래처명을 대조할 거래처 마스터가 정리되어 있는가
  • 확신이 낮은 문서를 보낼 확인 대기함과 확인 담당자를 정했는가
  • 원래 이름과 위치를 남기는 정리 기록이 있어 언제든 되돌릴 수 있는가
  • 계약서·인사 서류처럼 민감한 문서의 접근 권한과 외부 AI 전송 범위를 정했는가
  • 처음 몇 주는 자동 이동 없이 "정리 제안"만 만들어 사람이 결과를 검토하는가

특히 마지막 항목이 중요합니다. 처음부터 파일을 실제로 옮기기보다, 어떤 이름으로 어디에 둘지 제안 목록만 만들어 보고 오분류 유형을 확인한 뒤 자동 이동으로 넘어가는 것이 안전합니다.

FAQ

이미 쌓여 있는 수천 개의 파일도 한 번에 정리할 수 있나요?

가능하지만 새로 들어오는 문서부터 자동 정리를 적용하고, 기존 파일은 별도 작업으로 나눠 처리하는 편이 안전합니다. 기존 파일은 원본을 건드리지 않고 정리 결과를 목록으로 먼저 만든 뒤, 표본을 사람이 확인하고 나서 실제 이동과 이름 변경을 진행합니다.

AI가 문서 종류를 잘못 분류하면 어떻게 되나요?

분류 결과와 함께 확신 정도와 판단 근거를 남기고, 기준에 못 미치는 문서는 자동으로 옮기지 않고 확인 대기함에 둡니다. 또 원래 파일명과 위치를 기록해 두면 잘못 옮겨진 문서를 언제든 되돌릴 수 있습니다. 사람이 고친 결과는 규칙과 예시를 보완하는 데 다시 씁니다.

계약서처럼 민감한 문서를 외부 AI에 보내도 되나요?

회사의 보안 정책과 AI 서비스의 데이터 처리 조건을 먼저 확인해야 합니다. 분류에 필요한 앞부분 텍스트만 보내거나, 개인정보를 가린 뒤 보내거나, 사내 환경에서 동작하는 모델을 쓰는 방법이 있습니다. 어떤 문서를 어디까지 보낼지는 도입 전에 정해 두는 것이 좋습니다.
