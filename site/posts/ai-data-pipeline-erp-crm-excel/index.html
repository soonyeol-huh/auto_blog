ERP·CRM·엑셀을 AI에 연결하려면, 데이터 파이프라인부터 설계해야 합니다

AI에게 “이번 달 매출이 왜 떨어졌는지 알려줘”라고 묻고 싶다면 모델보다 먼저 확인할 것이 있습니다. ERP, CRM, 엑셀, 쇼핑몰의 숫자가 같은 기준으로 연결되어 있는가입니다. 실제 기업 AI의 품질은 모델만큼 데이터가 들어오는 길에 좌우됩니다.

문제는 데이터가 없는 것이 아니라 서로 다르게 존재한다는 것입니다

영업팀은 CRM의 계약 예정 금액을 보고, 재무팀은 ERP의 매출을 보고, 운영팀은 별도 엑셀에서 취소와 반품을 관리할 수 있습니다. 세 숫자는 모두 맞지만 의미와 갱신 시점이 다릅니다. 이 상태에서 AI가 여러 시스템을 직접 읽으면 그럴듯하지만 기준이 다른 답을 만들 수 있습니다.

따라서 첫 질문은 “어떤 LLM을 쓸까?”보다 “회사가 매출, 고객, 상품, 주문을 어떤 기준으로 정의할까?”가 되어야 합니다.

1. 시스템 목록보다 ‘업무 질문’을 먼저 정하세요

“ERP와 CRM을 모두 연결하자”는 요구는 범위가 너무 큽니다. 대신 “영업 책임자가 매일 오전 미수금과 계약 예정 고객을 한 화면에서 보고 싶다”처럼 실제 질문에서 시작합니다. 그러면 필요한 ERP 테이블, CRM 필드, 갱신 주기가 좁혀집니다.

2. 공통 키가 없으면 AI보다 데이터 통합이 먼저입니다

CRM의 고객명이 ‘보센 주식회사’이고 ERP에는 ‘(주)보센’으로 저장되어 있다면 문자열만으로 같은 고객인지 안정적으로 판단하기 어렵습니다. 고객 ID, 사업자 식별값, 내부 상품 코드처럼 시스템 사이를 잇는 키를 정하고 매핑 규칙을 관리해야 합니다.

3. 원본 데이터를 AI에 통째로 넘기지 마세요

AI가 필요한 것은 대개 전체 DB가 아니라 질문에 필요한 작은 데이터셋입니다. 예를 들어 “이번 주 이탈 위험 고객”을 찾는다면 최근 주문, 문의, 계약 상태처럼 필요한 필드만 API에서 만들어 제공할 수 있습니다. 이 구조는 비용과 응답시간뿐 아니라 권한 관리에도 유리합니다.

4. 실시간이 정말 필요한지 구분하세요

재고 확인은 수분 단위 갱신이 필요할 수 있지만 월간 경영 보고는 하루 한 번으로 충분할 수 있습니다. 모든 데이터를 실시간으로 만들면 비용과 장애 지점이 늘어납니다. 업무 의사결정에 필요한 신선도를 데이터별로 정의하는 것이 좋습니다.

5. 데이터 품질 실패를 AI가 숨기게 두지 마세요

전날 ERP 적재가 실패했는데 AI가 남아 있는 데이터로 자연스럽게 답하면 사용자는 문제를 알아차리기 어렵습니다. 최신 적재 시각, 누락 건수, 스키마 변경 등을 검사하고 기준을 벗어나면 AI 답변 전에 경고하거나 처리를 중단하는 장치가 필요합니다.

6. AI용 API는 업무 권한을 반영해야 합니다

대표와 영업사원이 볼 수 있는 고객 범위가 다르다면 AI도 같은 차이를 따라야 합니다. 사용자 인증 정보를 API 계층까지 전달하고 부서·담당자·데이터 등급에 따라 결과를 제한해야 합니다. AI 전용 관리자 계정 하나로 모든 데이터를 읽게 하는 방식은 운영 단계에서 위험해집니다.

실제 예시: 영업·매출 AI 대시보드

한 회사가 CRM에서 영업 기회를, ERP에서 실제 매출과 미수금을, 쇼핑몰에서 주문을, 엑셀에서 프로모션 일정을 관리한다고 가정해보겠습니다.

매일 새벽 각 데이터를 수집해 고객과 상품 ID를 맞추고 주문·취소·매출 기준을 정규화합니다. 적재 건수와 전일 대비 변화를 검사한 뒤 업무 API를 통해 “이번 주 매출”, “계약 예정 고객”, “미수금”, “프로모션 상품”을 제공합니다. AI는 이 API를 사용해 질문에 답하고 대시보드는 같은 데이터 계층을 사용합니다.

이렇게 하면 AI와 대시보드가 서로 다른 숫자를 보여주는 문제를 줄이고, 나중에 새로운 모델이나 에이전트를 붙여도 원천 시스템을 다시 연결할 필요가 줄어듭니다.

구축 순서는 작게 시작하는 편이 좋습니다

1단계: 질문 하나

매일 반복해서 확인하는 경영·영업·운영 질문 하나를 정합니다.

2단계: 데이터 2~3개

그 질문에 꼭 필요한 시스템만 연결합니다. 처음부터 전사 데이터를 모으지 않습니다.

3단계: 기준과 품질

공통 키, 계산식, 갱신 주기, 누락과 오류 기준을 문서화합니다.

4단계: API와 권한

AI와 화면이 필요한 정보만 가져갈 수 있는 인터페이스를 만듭니다.

5단계: AI 연결

FAQ

AI가 ERP와 CRM에 직접 접속하면 더 간단하지 않나요?

작은 PoC는 가능하지만 운영에서는 시스템별 정의, 권한, 장애, 호출 제한을 각각 처리해야 합니다. 여러 시스템을 쓰거나 AI 외에도 대시보드·API가 데이터를 사용한다면 중간 데이터 계층이 장기적으로 관리하기 쉽습니다.

데이터웨어하우스가 반드시 필요한가요?

아닙니다. 규모가 작으면 기존 DB와 API 계층만으로도 충분할 수 있습니다. 핵심은 특정 제품을 도입하는 것이 아니라 데이터 정의·품질·권한을 통제할 수 있는 구조를 만드는 것입니다.

엑셀도 자동으로 연결할 수 있나요?

가능합니다. 정해진 폴더나 스토리지의 파일을 주기적으로 읽고 검증해 DB에 적재할 수 있습니다. 다만 사람이 열 이름이나 파일 형식을 바꾸는 경우를 감지하고 알리는 절차가 중요합니다.
