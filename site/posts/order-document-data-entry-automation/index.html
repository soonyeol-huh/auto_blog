거래처 주문서·발주서, 아직 손으로 입력하고 계신가요?

거래처가 이메일로 보낸 PDF 주문서, 팩스로 온 발주서, 메신저로 찍어 보낸 사진을 담당자가 하나씩 열어 보고 ERP나 엑셀에 품목·수량·납기를 옮겨 적는 회사가 아직 많습니다. 주문서 입력은 문서 형태만 제각각일 뿐 하는 일은 매번 같아서, AI 문서 추출과 사람 검토를 조합하면 대부분 자동화할 수 있는 업무입니다. 이 글은 문서 수집부터 항목 추출, 품목 매칭, 검토 큐, 시스템 입력까지 이어지는 구조를 어떻게 만드는지 정리했습니다.

주문서 입력이 왜 아직 사람 손에 남아 있을까

주문 접수 자체는 오래전부터 시스템화된 회사가 많습니다. 문제는 그 시스템에 들어가기 전 단계입니다. 거래처는 우리 시스템에 맞춰 주문하지 않습니다. 각자 자기 회사 양식으로 발주서를 만들고, 이메일 본문에 품목을 적어 보내고, 급하면 전화로 부른 뒤 팩스로 확인서를 보냅니다. 이 문서들은 형태가 모두 달라서 정해진 칸을 읽는 전통적인 자동화로는 처리하기 어려웠고, 결국 사람이 읽고 옮겨 적는 일이 남았습니다. 그래서 주문이 늘면 입력 담당자를 늘려야 하고, 담당자가 자리를 비우면 주문이 밀리는 구조가 됩니다.

수기 입력에서 반복되는 문제

  • 오타와 단위 착오. 수량 100을 1,000으로, 박스 단위를 낱개로 입력하는 실수는 출고 뒤에야 발견되고, 되돌리는 비용이 입력 시간보다 훨씬 큽니다.
  • 품목 코드 찾기에 시간이 갑니다. 거래처가 적은 품명은 우리 시스템의 품목명과 다른 경우가 많아, 담당자가 매번 검색해서 맞는 코드를 골라야 합니다.
  • 처리 순서가 도착 순서가 아닙니다. 이메일함에 묻힌 주문서는 뒤늦게 발견되고, 납기가 촉박한 건이 먼저 처리된다는 보장이 없습니다.
  • 입력 현황이 보이지 않습니다. 어떤 주문서가 들어왔고 어디까지 입력됐는지가 담당자 메일함과 기억에만 있어, 거래처가 확인 전화를 하면 그제야 찾아봅니다.

이 문제들은 담당자의 숙련도 문제가 아니라, 형태가 다른 문서를 사람이 매번 해석해서 옮기는 구조 자체에서 생깁니다.

자동화 구조: 수집·추출·매칭·검토·입력

주문서 자동 입력은 다섯 단계를 순서대로 연결하는 구조입니다. AI가 맡는 부분은 두 번째 단계이고, 나머지는 규칙과 연동으로 처리합니다.

  1. 문서 수집. 주문 전용 이메일 주소, 팩스 수신함, 공유 폴더 등 주문서가 들어오는 창구를 정해 두고, 새 문서가 오면 자동으로 한곳에 모읍니다. 창구를 정리하는 것만으로도 누락이 크게 줄어듭니다.
  2. AI 항목 추출. 문서 형태와 관계없이 거래처명, 주문 번호, 품목, 수량, 단위, 단가, 납기, 배송지 같은 항목을 AI가 읽어 정해진 형식으로 정리합니다. 이미지 문서는 문자 인식(OCR)을 먼저 거칩니다.
  3. 품목·거래처 매칭. 추출된 거래처명과 품명을 우리 시스템의 거래처 코드와 품목 코드에 맞춥니다. 거래처별로 자주 쓰는 품명 표현을 별칭으로 저장해 두면 매칭 정확도가 올라갑니다.
  4. 검토 큐. 추출 신뢰도가 낮거나 매칭이 안 되거나 평소와 다른 주문은 자동 입력하지 않고 담당자 검토 화면으로 보냅니다.
  5. 시스템 입력. 확정된 주문을 ERP나 주문 관리 시스템에 등록하고, 거래처에 접수 확인을 보냅니다.

핵심은 네 번째 단계입니다. 목표는 사람을 없애는 것이 아니라, 담당자가 모든 주문서를 읽는 대신 확인이 필요한 건만 보게 만드는 것입니다.

어떤 문서까지 자동으로 읽을 수 있나

문서 형태에 따라 자동 처리 가능성이 다릅니다. 처음부터 모든 형태를 다루기보다 자동화하기 쉬운 것부터 시작하고, 어려운 형태는 사람 검토 비율을 높게 잡는 것이 현실적입니다.

신뢰도 기준과 검토 큐: 사람이 보는 건 어디까지

AI 추출은 틀릴 수 있다는 전제로 설계해야 합니다. 추출된 값마다 신뢰도를 남기고, 아래 조건 중 하나라도 해당하면 자동 입력을 멈추고 검토 큐로 보내는 것이 안전합니다.

  • 필수 항목(거래처, 품목, 수량, 납기) 중 하나라도 비어 있거나 신뢰도가 기준 이하일 때
  • 품명이 품목 코드에 매칭되지 않거나 후보가 여럿일 때
  • 수량이나 금액이 그 거래처의 평소 주문 범위를 크게 벗어날 때
  • 같은 주문 번호가 이미 등록되어 있을 때(중복 주문 가능성)
  • 납기가 오늘이거나 이미 지났을 때(긴급 건은 사람이 먼저 봐야 합니다)
검토 화면은 원본과 추출 결과를 나란히 보여 주어야 합니다. 담당자가 다시 문서를 열어 처음부터 읽어야 한다면 자동화의 의미가 없습니다. 원본 문서의 해당 부분을 표시하고 추출값을 바로 고칠 수 있게 하면 검토 시간은 건당 몇 초로 줄어듭니다. 그리고 담당자가 고친 내용, 예를 들어 어느 거래처의 어떤 품명이 우리 코드 무엇에 해당하는지는 별칭으로 저장해 다음부터는 자동으로 맞춰지게 합니다. 이렇게 하면 검토 큐에 들어오는 건수는 시간이 지날수록 줄어듭니다.

도입 전 체크리스트

  • 주문서가 들어오는 창구(이메일, 팩스, 메신저, 공유 폴더)를 모두 파악하고 있나요? 하나로 모을 수 있나요?
  • 월별 주문서 건수와 문서 형태별 비중을 대략 알고 있나요? 상위 거래처 몇 곳이 전체의 대부분을 차지하나요?
  • 품목 마스터에 거래처가 쓰는 품명 표현을 붙일 수 있는 자리가 있나요?
  • ERP나 주문 관리 시스템에 외부에서 주문을 등록할 방법(API, 업로드 양식 등)이 있나요?
  • 자동 입력된 주문과 사람이 확인한 주문을 구분해서 나중에 추적할 수 있나요?
  • 거래처에 보내는 접수 확인 문구와 발송 시점을 담당 부서와 합의했나요?

자주 하는 실수

  • 모든 추출 결과를 그대로 입력하는 것 — 수량 오류가 출고까지 이어지면 되돌리는 비용이 큽니다. 확실한 건만 자동 입력하고 나머지는 검토 큐로 보내야 합니다.
  • 모든 거래처, 모든 문서 형태를 한 번에 시작하는 것 — 주문 건수가 많고 문서가 깔끔한 거래처 몇 곳으로 시작해 정확도를 확인한 뒤 넓히는 것이 빠릅니다.
  • 품목 매칭을 AI에만 맡기는 것 — 비슷한 품명이 여럿 있을 때 AI 추측에 의존하면 엉뚱한 품목이 등록됩니다. 거래처별 품명 별칭 사전을 만들고 매칭이 애매하면 사람에게 넘깁니다.
  • 검토 결과를 다시 반영하지 않는 것 — 같은 거래처의 같은 품명을 매번 다시 확인하게 됩니다. 담당자의 수정이 규칙으로 쌓이도록 설계해야 합니다.
  • 입력만 자동화하고 접수 확인은 그대로 두는 것 — 거래처의 확인 전화는 여전히 담당자에게 옵니다. 접수 확인 발송까지 연결해야 담당자 시간이 실제로 돌아옵니다.

FAQ

거래처마다 주문서 양식이 다 다른데 자동으로 읽을 수 있나요?

양식이 제각각인 것이 바로 AI 추출을 쓰는 이유입니다. 정해진 칸 위치를 읽는 방식과 달리, AI는 문서 안에서 거래처명·품목·수량·납기 같은 항목을 의미 기준으로 찾아내므로 양식이 달라도 같은 결과 형태로 정리할 수 있습니다. 다만 처음부터 모든 거래처를 넣기보다 주문 건수가 많은 상위 거래처 몇 곳으로 시작해 추출 결과를 검증하고, 그다음 범위를 넓히는 것이 안전합니다.

AI가 수량이나 금액을 잘못 읽으면 어떻게 하나요?

잘못 읽을 수 있다는 전제로 구조를 설계해야 합니다. 추출된 값마다 신뢰도를 남기고, 신뢰도가 낮거나 품목 코드와 매칭되지 않거나 평소 주문 패턴과 크게 다른 건은 ERP에 자동 입력하지 않고 담당자 검토 큐로 보냅니다. 검토 화면에는 원본 문서와 추출 결과를 나란히 보여 주어 담당자가 몇 초 안에 확인하고 수정할 수 있게 하고, 수정 내역은 다음 추출의 규칙으로 다시 반영합니다.

팩스나 스캔한 이미지로 오는 주문서도 처리되나요?

가능하지만 텍스트 PDF나 이메일 본문보다 인식 정확도가 낮을 수 있습니다. 이미지 문서는 먼저 문자 인식(OCR) 단계를 거친 뒤 AI 추출로 넘기며, 해상도가 낮거나 손글씨가 섞인 문서는 신뢰도 기준을 더 엄격하게 잡아 사람 검토 비율을 높이는 것이 현실적입니다. 팩스 비중이 높다면 주요 거래처에 PDF나 이메일로 보내 달라고 요청하는 것만으로도 자동 처리율이 크게 달라집니다.
