AI 외주 계약서, 구축 전에 꼭 정해야 할 7가지

제안서를 비교해 업체를 골랐다면 다음은 계약입니다. AI 프로젝트는 일반 웹 개발보다 외부 모델·데이터·API·클라우드가 많이 얽히기 때문에 누가 무엇을 소유하고, 운영비를 누가 내며, 어디까지 유지보수하는지를 구축 전에 정해두는 것이 중요합니다.

계약서에서 특히 달라지는 부분

예를 들어 고객 문의 AI를 구축한다고 해보겠습니다. 주문 데이터는 회사 것이지만, 답변에는 외부 LLM이 사용되고 CRM API와 클라우드도 연결됩니다. 개발사가 만든 코드와 프롬프트, 벡터 검색 설정, 운영 로그도 생깁니다. “고객 상담 AI 구축” 한 줄만으로는 프로젝트가 끝난 뒤 누가 무엇을 관리해야 하는지 알기 어렵습니다.

1. 회사 데이터의 소유권과 반출 범위

원본 데이터뿐 아니라 프로젝트 과정에서 정제한 데이터, 임베딩·색인, 상담 로그, 평가 데이터가 누구에게 귀속되는지 확인해야 합니다. 계약 종료 시 반환 또는 삭제 범위도 함께 정하는 편이 좋습니다.

2. 소스코드와 기술 문서의 인수인계

“개발 완료”와 “회사가 직접 운영 가능”은 다릅니다. 저장소 접근권한, 환경변수 목록, 데이터 구조, API 명세, 배포 절차, 장애 대응 방법까지 있어야 내부 개발자나 다음 업체가 이어받기 쉽습니다.

계약 전에 확인할 문장:
“프로젝트 종료 시 운영에 필요한 소스, 설정, API 목록, 배포 문서와 관리자 권한을 어떤 형태로 인계합니까?”

3. LLM·API·클라우드 비용의 부담 주체

AI 프로젝트에는 모델 사용료 외에도 검색·데이터 수집·문자·메일·클라우드 비용 등이 붙을 수 있습니다. 개발비에 포함인지 별도인지, 업체가 재판매하는지 회사 계정으로 직접 결제하는지 구분해야 합니다.

비용은 월 총액보다 구조를 보세요

사용량이 늘면 함께 증가하는 비용과 고정 비용을 분리하면 운영 규모가 커질 때 예산을 예측하기 쉽습니다. 사용량을 회사가 직접 확인할 수 있는지도 중요합니다.

4. 클라우드와 외부 서비스 계정은 누구 명의인가

가능하다면 핵심 운영 계정은 발주사가 소유하고 개발사에 필요한 권한을 부여하는 구조가 인수인계에 유리합니다. 계약 종료 뒤에도 서비스가 계속 돌아가야 하기 때문입니다.

5. ‘완료’와 ‘검수 통과’의 기준

“AI 상담 기능 개발 완료”처럼 추상적인 조건보다 테스트할 수 있는 업무 시나리오를 정하는 편이 좋습니다. 예를 들어 주문 조회, 일반 문의 답변 초안, 환불 요청의 담당자 이관 등 핵심 시나리오가 정상 동작하는지 검수할 수 있습니다.

AI 결과는 항상 같은 문장이 나오지 않을 수 있으므로 단순 문구 일치보다 허용·금지 행동, 필수 정보 포함, 사람 이관 조건처럼 업무 기준으로 평가하는 것이 현실적입니다.

6. 장애와 기능 변경을 구분하세요

기존 합의 기능이 동작하지 않는 장애와 새로운 요구사항 추가는 다릅니다. 외부 API 규격 변경이나 모델 변경처럼 양쪽 책임만으로 설명하기 어려운 상황도 있습니다. 무엇이 무상 수정이고 무엇이 별도 작업인지 기준을 정해야 합니다.

7. 유지보수는 ‘몇 개월’보다 대응 범위를 보세요

유지보수 3개월이라는 문장만으로는 부족합니다. 장애 접수 채널, 심각도별 대응 목표, 모니터링 범위, 데이터·프롬프트 수정 포함 여부, 월 지원 시간 등을 확인하면 실제 운영 지원 수준을 비교하기 쉽습니다.

실제 업무 예시: CRM 연동 영업 AI

영업팀이 CRM 고객 정보를 읽고 상담 내용을 요약해 다음 행동을 추천하는 AI를 외주로 구축한다고 가정해보겠습니다. 계약에는 CRM 접근은 조회 전용인지, AI가 메모를 직접 저장할 수 있는지, 외부 LLM으로 어떤 데이터가 전달되는지, 생성된 로그는 어디에 저장되는지까지 반영할 필요가 있습니다.

여기에 CRM API가 바뀌었을 때 수정 책임, 모델 사용료, 월 호출 한도, 프로젝트 종료 후 소스와 클라우드 계정 인계까지 정해두면 기술 문제가 곧바로 계약 문제로 번지는 일을 줄일 수 있습니다.

  3. LLM·외부 API·클라우드 비용 부담과 과금 기준이 적혀 있는가?
  4. 핵심 서비스 계정과 관리자 권한의 소유자가 명확한가?
  5. 검수 통과를 판단할 업무 시나리오가 정의돼 있는가?

FAQ

AI 외주 계약에서 소스코드는 반드시 받아야 하나요?

운영과 후속 개발을 내부 또는 다른 업체가 이어갈 가능성이 있다면 저장소 접근권한, 소스코드 귀속, 배포 방법과 기술 문서 인수인계 조건을 명시하는 것이 좋습니다.

LLM이나 외부 API 비용도 계약서에 넣어야 하나요?

네. 모델, 데이터 수집, 메시징, 클라우드 등 사용량에 따라 늘어나는 비용의 부담 주체와 과금 기준, 사용량 확인 방법을 정해두는 편이 좋습니다.

유지보수는 기간만 정하면 되나요?

기간뿐 아니라 장애와 기능 변경의 구분, 대응 시간, 포함 작업, 별도 비용이 발생하는 조건을 함께 정해야 운영 단계의 분쟁을 줄일 수 있습니다.
