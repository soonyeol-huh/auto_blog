같은 고객 주소가 세 가지로 적혀 있다면?

"서울 강남구 역삼동 ○○번지", "서울특별시 강남구 테헤란로 ○○", "강남 역삼 ○○빌딩 3층". 같은 곳인데 CRM, 주문 시스템, 엑셀 명단에 전부 다르게 적혀 있는 경우는 흔합니다. 이 상태로는 지역별 매출을 집계하거나, 담당 구역을 나누거나, 같은 고객을 찾아내는 일이 매번 손작업이 됩니다. 주소는 공공 주소 데이터라는 정답지가 있는 몇 안 되는 데이터라서, 원본을 보존한 채 표준 주소로 정리하고 새로 들어오는 주소는 입력 단계에서 검증하는 구조를 만들 수 있습니다. 이 글은 그 순서와 주의할 점을 정리합니다.

주소가 제각각이 되는 이유

주소가 흐트러지는 건 누가 잘못해서라기보다 입력 경로가 여러 개이기 때문입니다.

  • 표기 방식이 섞여 있습니다. 도로명주소가 법정 주소로 쓰인 지 오래됐지만, 오래된 고객 데이터나 사람들의 습관에는 지번주소가 여전히 많이 남아 있습니다.
  • 줄임말과 오타가 많습니다. "서울시", "서울특별시", "서울"이 섞이고, 동 이름이나 번지가 빠지거나 틀린 채로 저장됩니다.
  • 한 칸에 여러 정보가 들어갑니다. 주소 칸에 층·호수, 건물명, "경비실에 맡겨 주세요" 같은 요청사항까지 함께 적힙니다.
  • 행정구역이 바뀝니다. 시군구 통합이나 명칭 변경, 도로명 변경이 생기면 예전에 맞았던 주소도 현재 기준과 달라집니다.
  • 시스템마다 형식이 다릅니다. 한 곳은 주소를 한 칸에, 다른 곳은 시·구·상세로 나눠 저장해서 그대로는 서로 비교가 안 됩니다.

방치하면 생기는 문제

업무주소가 흐트러져 있을 때
지역별 매출·고객 분석같은 구가 여러 이름으로 집계되어 숫자가 쪼개지거나 빠짐
영업·배송 구역 배정주소에서 시군구를 사람이 직접 읽어 배정해야 함
중복 고객 찾기같은 사업장이 주소 표기만 달라 다른 고객으로 남음
우편물·배송우편번호 누락이나 오래된 주소로 반송·지연 발생
외부 데이터 결합공공 통계, 상권 데이터와 행정구역 코드로 연결할 수 없음

결국 주소 문제는 주소 칸 하나의 문제가 아니라, 지역 단위로 판단하는 모든 업무의 정확도 문제입니다.

정답지는 이미 있다: 공공 주소 데이터

행정안전부는 도로명주소 개발자센터를 통해 주소 검색 API와 도로명주소 데이터를 공개하고 있습니다. 입력한 주소를 검색하면 표준 도로명주소와 지번주소, 우편번호(기초구역번호), 행정구역 코드 같은 항목을 함께 받을 수 있고, 좌표 정보를 제공하는 API와 전체 주소 데이터 파일도 제공됩니다. 이용하려면 사용 신청과 승인키 발급이 필요하고, 호출 방식과 제공 항목은 공식 문서에서 확인해야 합니다.

"우리가 정하는 기준"이 아니라 "공공 기준"에 맞추세요. 사내에서 표기 규칙을 새로 만들면 또 하나의 형식이 생길 뿐입니다. 공공 주소 데이터의 결과값을 표준으로 삼으면, 다른 시스템이나 외부 데이터와 연결할 때도 같은 기준을 쓸 수 있습니다.

정제 구조: 원본은 두고, 표준값을 옆에 붙인다

  1. 원본 보존 — 고객이 입력한 주소는 지우거나 덮어쓰지 않고 그대로 둡니다. 정제 결과는 별도 필드에 저장합니다.
  2. 사전 정리 — 앞뒤 공백, 특수문자, 반복 표기를 정리하고 "서울시"→"서울특별시" 같은 흔한 줄임말을 규칙으로 맞춥니다. 층·호수와 요청사항은 상세주소 칸으로 분리합니다.
  3. 공공 주소 대조 — 정리된 주소로 주소 검색 API를 호출하거나 주소 데이터 파일과 대조해 후보를 찾습니다.
  4. 결과 분류 — 후보가 정확히 하나면 자동 확정, 여러 개거나 없으면 확인 목록으로 보냅니다. 자동 확정 기준은 처음에는 보수적으로 잡습니다.
  5. 표준값 저장 — 도로명주소, 지번주소, 우편번호, 시도·시군구 코드, 필요하면 좌표를 저장하고, 언제 어떤 방식으로 정제됐는지 기록합니다.
  6. 정기 재점검 — 주소 데이터가 갱신되면 저장된 표준값을 다시 대조해, 행정구역이나 도로명이 바뀐 건을 찾아 업데이트합니다.

규칙과 AI, 사람의 역할 나누기

단계처리 방식이유
공백·줄임말 정리, 우편번호 형식 점검규칙같은 입력에 항상 같은 결과가 나와야 함
표준 주소 확정공공 주소 데이터 대조주소의 정답은 공공 데이터에 있음
메모란에 섞인 주소 골라내기, 주소와 요청사항 분리AI(검토 전제)형식이 정해지지 않은 자유 입력을 나누는 작업
후보가 여럿이거나 없는 주소사람 확인잘못 확정하면 다른 고객·다른 장소로 연결됨
고객에게 주소 재확인 요청사람(안내 문구는 자동화 가능)고객 접점은 회사 정책에 맞춰 판단

AI가 주소를 "그럴듯하게" 완성하게 두는 것은 피해야 합니다. 없는 번지를 만들어 넣을 수 있기 때문에, AI의 결과도 반드시 공공 주소 데이터 대조를 통과해야 확정되도록 설계합니다.

새는 곳을 막는다: 입력 단계 검증

기존 데이터를 한 번 정리해도 입력 경로가 그대로면 몇 달 뒤 같은 상태로 돌아갑니다. 정제와 함께 입력 단계를 바꾸는 것이 중요합니다.

  • 주소 검색 입력 — 웹 폼과 사내 입력 화면에서는 주소를 직접 타이핑하는 대신 검색해서 선택하게 하고, 상세주소만 따로 입력받습니다.
  • 일괄 업로드 검증 — 엑셀로 들어오는 명단은 업로드 시점에 주소를 대조해, 확정되지 않는 행을 바로 표시합니다.
  • 시스템 간 기준 통일 — CRM, 주문, 배송 시스템이 같은 표준 주소 필드를 쓰도록 맞추고, 연동할 때는 표준값을 기준으로 주고받습니다.
  • 품질 지표 관리 — 표준 주소가 확정된 비율, 확인 목록에 쌓인 건수를 매주 보면서 어느 입력 경로에서 문제가 생기는지 확인합니다.

  • 주소가 저장된 시스템과 파일 목록, 각각의 주소 필드 형식을 정리했는가
  • 원본 주소를 보존하고 표준값을 별도 필드에 둘 수 있는가
  • 주소 검색 API 사용 신청과 이용 조건, 호출 한도를 확인했는가
  • 자동 확정 기준과 확인 목록 담당자를 정했는가
  • 고객 주소는 개인정보이므로 처리 범위, 접근 권한, 외부 전송 여부를 내부 기준에 맞게 정했는가
  • 정제 후 지역별 집계나 중복 고객 대조처럼 바로 쓸 업무를 하나 정했는가

FAQ

주소 정제를 하면 기존에 저장된 주소는 지워지나요?

지우지 않는 것이 원칙입니다. 고객이 입력한 원본 주소는 그대로 두고, 표준화된 도로명주소·우편번호·행정구역 코드는 별도 필드에 저장합니다. 그래야 정제 결과가 틀렸을 때 원본과 비교해 바로잡을 수 있고, 어떤 기준으로 바뀌었는지도 설명할 수 있습니다.

주소 검색 API를 쓰면 모든 주소가 자동으로 정리되나요?

형식이 비교적 온전한 주소는 대부분 하나의 결과로 정리되지만, 오타가 많거나 건물명만 적혀 있거나 검색 결과가 여러 건 나오는 주소는 자동으로 하나를 고르면 안 됩니다. 이런 주소는 후보와 함께 확인 목록으로 보내고, 필요하면 고객에게 다시 확인하는 흐름을 둡니다.

AI는 주소 정제에서 어떤 역할을 하나요?

최종 주소 확정은 공공 주소 데이터 대조와 규칙으로 처리해야 결과가 일정합니다. AI는 메모란이나 자유 입력 칸에 섞인 주소를 골라내거나, 주소와 상세 정보(층·호수·배송 요청사항)를 나누거나, 확인 목록에 올라온 애매한 주소의 후보를 설명하는 보조 작업에 쓰는 것이 적합합니다.
