"그 구매 건 승인 났어요?" 아직 메신저로 물어보고 계신가요

사무용품 하나, 소프트웨어 구독 하나를 사려 해도 요청은 메신저로, 견적은 메일로, 승인은 구두로 오갑니다. 며칠 뒤에는 요청한 사람도 승인할 사람도 그 건이 어디서 멈췄는지 모릅니다. 구매 승인이 느린 이유는 승인자가 바빠서만이 아니라 요청 정보와 승인 기준과 진행 상태가 한곳에 모여 있지 않아서입니다.

구매 요청이 중간에서 멈추는 이유

구매 요청은 대부분 자유 형식으로 들어옵니다. "모니터 하나 필요합니다" 같은 메시지에는 수량·용도·예산 항목·희망 납기가 빠져 있기 일쑤라, 승인자는 승인하기 전에 다시 질문해야 하고 그 사이 요청은 대화창 위로 밀려 올라갑니다.

승인 경로도 사람의 기억에 의존합니다. 얼마 이상이면 팀장 다음에 누구를 거쳐야 하는지, 어떤 품목은 IT 담당자 확인이 필요한지가 문서로 정리돼 있지 않으면 요청자는 매번 물어보고, 승인자는 자기 차례인지도 모른 채 시간이 흐릅니다. 승인 뒤 발주와 입고 확인까지 이어지는 흐름이 끊겨 있으면 "승인은 났는데 주문은 누가 했죠?"라는 질문이 또 생깁니다.

발주 등록승인된 건을 발주서 형식이나 ERP 입력 형식으로 변환거래처·조건 최종 확인
입고·완료 확인납기 기준으로 입고 확인 요청, 완료 시 요청자에게 알림수령 확인

이 흐름에서 자동화의 목표는 승인 자체를 없애는 것이 아니라, 승인자가 판단에 필요한 정보가 다 갖춰진 상태로 요청을 받게 만드는 것입니다.

승인 경로는 규칙으로 정한다

대부분의 회사에는 이미 암묵적인 승인 기준이 있습니다. 이를 표로 꺼내 정리하면 시스템이 그대로 따를 수 있습니다.

  • 금액 구간: 일정 금액 미만은 팀장 승인, 그 이상은 재무 담당자나 대표 승인 추가
  • 품목 유형: 소프트웨어·장비는 IT 담당자 확인, 외주 용역은 계약 담당자 확인
  • 예산 상태: 예산 범위 안이면 기본 경로, 초과하면 예산 책임자 승인 추가
  • 반복 구매: 사전에 정한 소모품 목록과 금액 한도 안의 정기 구매는 간소화된 경로
규칙이 애매한 부분을 AI에게 맡기지 마세요. 승인 경로는 누가 책임지는지를 정하는 일이라 예측 가능해야 합니다. 기준이 모호하다면 먼저 사람끼리 기준을 정하고, 그 결과를 규칙으로 옮기는 순서가 맞습니다.

금액 기준을 피하려고 요청을 여러 건으로 나누는 경우도 규칙으로 잡을 수 있습니다. 같은 요청자·같은 품목·짧은 기간 안의 요청을 합산해 기준을 넘으면 상위 승인 경로로 올리는 식입니다.

AI가 맡을 수 있는 일과 맡기면 안 되는 일

AI는 규칙 위에서 정보를 정리하는 역할을 할 때 가장 유용합니다.

  • 요청자가 자유롭게 쓴 설명을 품목명·수량·용도로 나눠 양식에 채우는 일
  • 품목 설명을 보고 사무용품·장비·소프트웨어·용역 같은 분류 후보를 제안하는 일
  • 비슷한 과거 요청과 당시 구매 금액·거래처를 찾아 승인자에게 함께 보여주는 일
  • 승인자에게 "예산 잔액 대비 비중, 최근 동일 품목 구매 여부" 같은 확인 포인트를 요약하는 일

반대로 승인 여부 결정, 거래처 선정, 계약 조건 판단은 AI가 확정하지 않도록 설계해야 합니다. AI의 분류나 요약이 틀릴 수 있다는 전제로, 승인 화면에는 원본 요청 내용을 항상 함께 보여주는 것이 안전합니다.

지연 알림과 진행 상태 공유

승인 자동화에서 체감 효과가 큰 부분은 "지금 어디서 멈춰 있는가"를 누구나 볼 수 있게 하는 것입니다.

  1. 상태 표준화: 접수·보완 요청·승인 대기·승인 완료·발주 완료·입고 완료처럼 상태를 정해 모든 요청에 붙입니다.
  2. 지연 기준: 승인 대기 상태가 정해진 기간을 넘으면 승인자에게 다시 알리고, 그래도 처리되지 않으면 대리 승인자나 관리자에게 알립니다.
  3. 요청자 알림: 상태가 바뀔 때마다 요청자에게 자동으로 알려 확인 연락을 줄입니다.
  4. 부재 처리: 휴가·출장 중인 승인자를 미리 등록해 두면 대리 승인 경로로 자동 전환합니다.

요청별 처리 기간과 반려 사유를 쌓아 두면, 어느 단계에서 자주 멈추는지와 어떤 정보가 자주 빠지는지가 드러나 양식과 규칙을 개선할 근거가 됩니다.

FAQ

소규모 회사도 구매 승인 자동화가 필요한가요?

승인자가 한두 명뿐이라도 요청이 메신저·메일·구두로 들어와 누가 무엇을 요청했는지 추적하기 어렵다면 효과가 있습니다. 처음에는 요청 양식 하나와 진행 상태 목록만 만들어도 "그 건 어떻게 됐어요?" 같은 확인 연락이 크게 줄어듭니다.

AI가 구매 승인 여부를 직접 결정해도 되나요?

권장하지 않습니다. AI는 요청 내용을 정리하고 품목 분류나 비슷한 과거 요청을 찾아 승인자에게 보여주는 데 유용하지만, 예산 집행과 거래처 선정은 책임이 따르는 결정이므로 사람이 승인해야 합니다. 금액이 작고 규칙이 명확한 건만 사전에 정한 기준으로 자동 승인하는 정도가 안전합니다.

이미 쓰고 있는 전자결재나 ERP가 있으면 어떻게 하나요?

기존 시스템을 바꾸지 않고 앞뒤 단계를 연결하는 방식으로 시작할 수 있습니다. 요청 접수와 정리, 승인 경로 판단, 지연 알림은 자동화하고, 최종 결재와 발주 등록은 기존 시스템의 API나 정해진 입력 형식으로 넘기는 구조가 일반적입니다.
